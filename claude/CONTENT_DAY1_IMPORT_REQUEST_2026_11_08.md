【中身U1：1日目の台本・ニュース・タイムラインをゲームのデータに入れる】

■ 背景
1日目の中身（常連3人・モブ2組・昼市場の会話・ニュース・タイムライン）が文章でできた。
これをゲームのデータに入れ、1日目を本番の文で通して遊べるようにする。2日目以降は、今の仮の文のまま。

■ 元の文（planning/scenario/day1/ に置いてある8本）
- 1日目_運び屋.md（阿強・宵の口）／1日目_港湾労働者の二人.md（モブ・宵の口）
- 1日目_チンピラ.md（レックス・夜半）／1日目_安宿の夜勤受付.md（モブ・夜半）
- 1日目_老婆.md（ターニャ婆・明け方）／1日目_昼市場の仕入れ会話.md（朝）
- 1日目_ニュース.md／1日目_タイムライン.md

■ 文の表記の決まり（元の文に書いてあるとおり）
- 「名前「セリフ」」の行だけを会話枠に出す。
- 〔演出〕の行は、絵・音・動きの書き置き。画面に文字として出さない。データには残してよい（あとで演出を付けるため。
  表示しない種類の行として持つか、別の欄に持つかは任せる。報告する）。
- 〔ゲーム〕の行は、ゲームの処理の説明。データにする必要はない（処理の位置を合わせるために読む）。
- 判定の反応は GREAT／GOOD／OK／BAD のうち、判定の結果の1行だけを出す。書いていない段（モブの GREAT など）は出さない。
- 港湾労働者の OK は「どちらの札が外れたか」で2通りある。今の作りで分けられなければ、1つ目の OK だけを使ってよい（報告する）。

■ やること
1. 常連の場面データ（data/episodes/）
   - delivery_man_01・thug_01・granny_01 の本文を、元の文に差し替える。
   - 来店の挨拶〜注文、杯ごとの提供の前の会話、反応、食後の会話、会計、退店の流れを、今の場面データの欄（greet・cups の adjust・serve・reactions・after_talk など）に割り当てる。
     今の欄で入らない流れ（例：阿強の2杯目の、注文から提供までの会話）があれば、最小の欄を足してよい。どう割り当てたかを報告する。
   - 注文の札（データ）：阿強の1・2杯目＝辛い＋スタミナ（好物 豆腐）。3杯目（持ち帰り）＝**うましお＋やさしい**（今のデータ まろやか＋やさしい から変える）。
     レックス＝まろやか＋やさしい（好物 肉団子）。ターニャ婆＝うましお＋腹もち（好物 モツ）。今のデータと違うところがあれば報告する。
2. モブ（data/mobs/）
   - 港湾労働者（辛い＋スタミナ）・安宿の夜勤受付（まろやか＋やさしい）の1日目の挨拶・反応を、元の文にする。
     モブの文が日ごとに持てない作りなら、1日目の分を持てる最小の形を足す（2日目以降は今の文のまま）。どうしたかを報告する。
   - 安宿の夜勤受付は、文では「一人で来て二杯持ち帰る」。データの1日目は「2人・2杯」。
     今の作りが「人数＝杯数」なら、杯数2はそのままにして、文の上だけ一人で来る形でよい（表示の人数が出るなら報告する）。
3. 名前
   - 阿強・レックス・ターニャ婆は、店主が前から名前を知っている常連。1日目の最初から、この名前で出す
     （今の「配達員→阿強」のように途中で名前が分かる切り替えは、この3人では使わない）。
     名前が出る場所（会話枠・DMの差出人・連絡先のカード・結果画面）がそろうこと。新人警官・夜の女・配信者は今のまま。
4. 1日目の朝に、昼市場の会話（炭屋サミル→水場の梁伯→張記の張姐）を決まった順で出す。
   - 1日目に買い物の市場は無い（market_open_from_day＝2）。選ぶ操作なしの場面として、目覚めのあと・準備の前に入れる。
   - 水道代（bills の water 五十、scene "water_stall"）は梁伯の場面で払う。場所代（rent 九十、scene "thug"）はレックスの場面で払う（今のまま）。
     今の作りで支払いの場面がどこにあるかを確かめ、文と合うように置く。
5. ニュース（data/news/week7.json）の1日目を、1日目_ニュース.md の4本にする。1本目は must_info ①（ストが始まった）のまま。
6. タイムライン（data/sns/week7.json）
   - 今入っている試しの仮データ（夜歩きカメラ・ノイズ・港の荷役など21件）は、新しい筋と合わないので全部外す。
   - 1日目_タイムライン.md のアカウント7つと投稿8件を入れる。返信先、写真（仮の枠の説明）、
     書き手用の本当の意味（リンの裏アカの原文と意味など）は truth の欄へ。
   - 2日目以降の投稿は、今回は無し（空でよい）。
7. 文の検査
   - 会話枠に出す文に〔演出〕〔ゲーム〕が混ざっていないこと。
   - 遊びに効く文（注文の手がかり）と、データの注文の札が合っていること（目で確かめた結果を報告でよい）。

■ 自動試遊（v2）について
阿強の3杯目の札を変えると、自動試遊の結果が変わり、v2 との全キー一致が崩れる見込み。
- 札の変更は、文の差し替えとは別のコミットにする。
- 崩れたら、どのキーがどう違うかを報告して、そこで止める（v2 の基準は上書きしない）。基準の作り直しは、こちらで決める。

■ 確かめること・報告
- Day1 を最初から閉店まで通して、文が順に出ること。〔演出〕が出ないこと。反応が判定どおりに1行だけ出ること。
- スクリーンショット：朝の市場の会話（水場）、阿強の注文の場面、反応の場面、タイムライン（2日目の朝）、ニュースの一覧。
- 文が長くて会話枠からはみ出す行があれば、一覧で報告（文はこちらで直す）。
