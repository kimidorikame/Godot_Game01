# 夜湯：21日版と長期経営版への拡張ロードマップ

作成日：2026-09-23  
状態：将来設計の提案。ゲームへの実装・採用・プレイ検証は行っていない。

参照した添付案：`Night_Broth_Balance_Proposal_ClaudeCode.md`、`BALANCE_REDESIGN_PLAN.md`。両案の数値や「承認が必要」とする記述は比較資料として扱い、この文書の決定済み条件とはしない。

この文書は、まず7日版で成立させる経営を、21日間の物語と、その後の物語に依存しない長期経営へ広げるための設計である。7日版の最終採用値が変わっても、拡張順序と検証方法は使える。

## 1. 先に7日版で完成させるもの

7日版の目的は、需要を見て仕込みと食材を選び、失敗しても次の営業で改善できることである。拡張のために基本営業の完成を遅らせない。

| 7日版で必要 | 将来へ残す |
|---|---|
| 一日の需要と時間帯別の混雑予告 | 天候・曜日・地域イベントによる需要変動 |
| 味と具の嗜好、好物の発見 | 客層ごとの常連化、予約・紹介 |
| 仕込み量、水、だしの役割分担 | 鍋容量・保冷・営業形態への投資 |
| 断る操作、品切れの記録、重要会話の到達保証 | 予約枠・当日枠・満席後の待ち客の管理 |
| 鮮度と在庫消費の説明の一致 | 食材別の保存設備や仕入れ契約 |
| 現金・消費原価・廃棄・未提供の記録 | 設備の回収、長期の資産と運転資金の管理 |
| 同じ需要条件で比較できる再現手段 | 21日・90日・180日の戦略比較 |

7日版には、設備ツリー、従業員のシフト、借入金利、変動相場、複数店舗、自由なメニュー値付け、客ごとの大量の数値を追加しない。毎朝の需要予測に差が出ないまま、計器だけ増やさない。

将来を見越して7日版で残したいのは、日程と数値設定を分けること、在庫ロットと注文実績を記録すること、需要抽選を反応台詞の乱数から分けること、日次集計の形式を揃えることまででよい。汎用の経営エンジンを先に作る必要はない。

## 2. 21日は7日を三回繰り返さない

| 期間 | 中心となる判断 | 新しく起こること | 到達状態 |
|---|---|---|---|
| Day1〜7：営業を覚える | 今夜の量と食材を揃える | 好物の発見、予測と実績の照合、失敗からの回復 | 自分なりの安定した営業ができる |
| Day8〜14：店の方針を選ぶ | 何に投資し、誰の需要を受けるか | 設備候補を最大2系統、事前予告のある混雑日、常連の再来店 | 大量販売と、廃棄を抑えた営業に異なる強みがある |
| Day15〜21：選んだ方針を仕上げる | 残り日数で回収できるか、品質と積立をどう配分するか | 既知の条件を組み合わせた忙しい日、人物の結末、投資の成果確認 | 買い増しを止めて現金を残す判断も成立する |

週の切り替わりで、全食材の価格・腐敗日数・要求タグを一斉変更しない。週2では設備、週3では需要の組み合わせというように、覚えるルールを抑える。

物語の常連枠を機械的に21枠から63枠へ増やさない。週2以降は、通常日は物語を進める来店を1〜2件、節目の日だけ最大3件とする案から始める。常連の顔は見せつつ、同じ好物を毎晩入れるだけの繰り返しを避ける。この件数はシナリオ量・一晩の所要時間に合わせる未検証の目安である。

## 3. 需要と容量を別々に伸ばす

7日版の供給上限を `S7` とする。21日版でも、鍋の物理容量、朝の仕込み量、一晩に提供できる最大量、実際に調理する注文数を別の値として扱う。

仮に7日基準として一晩最大18杯を採用した場合の検討例は次のとおり。数値は未検証であり、7日基準の決定後に置き換える。

| 段階 | 一晩の供給上限の候補 | 予告される潜在需要の例 | 注意点 |
|---|---:|---:|---|
| 週1 | 18杯 | 6〜18杯 | まず通常営業で需要と供給を合わせられるようにする |
| 週2・初回拡張後 | 22杯、すなわち `S7＋4` | 12〜24杯 | 上限超過分は待ち客として見せ、必須注文へ勝手に追加しない |
| 週3・次の拡張を選んだ場合 | 26杯、すなわち `S7＋8` | 14〜28杯 | 未拡張の18杯営業も別の目標で完走可能にする |

需要幅は低評判から高評判までを含む全体の例であり、「週が変われば最低12杯来る」という無条件の保証ではない。各朝は現在の評判・客層・予告イベントから、もっと狭い予測幅を出す。

設備を買っただけで、需要を同じだけ増やさない。拡張前の売り逃しや予告された混雑があり、その機会を売上にできるから容量へ投資する。追加需要がない日に拡張しても採算は改善しない。

水の回数を週ごとに増やして供給を伸ばす方法は優先しない。仕込み量と鍋容量を増やし、水・だしは営業中の調整という役割を保つ。給水の繰り返しが増えるだけなら、まとめ操作にして手間を減らす。

杯数が増えても、手動調理の件数を同じ比率で増やさない。団体は1〜4人を基本にし、再来店の定型注文には保存したレシピを使える案を週2以降に検討する。保存レシピでも、在庫・人数・鮮度の確認と消費は省略しない。一晩の操作時間を測ってから追加する。

## 4. 評判が高いほど不利になる循環を避ける

Claude Code案の来店ごとの固定加点は、長期では上限へ張り付きやすい。一方、再設計案の「全潜在需要の未提供を0点にする」方式も、需要が容量を超える拡張では、高評判→過剰需要→未提供→評判低下を繰り返す原因になる。

21日版では、次の区別を追加する。

| 区分 | 扱い |
|---|---|
| 朝に予告した受付上限の範囲で到着する注文 | 営業品質の対象。勝手に母数から除外しない |
| 引き受けた注文を出せなかった | 未提供として品質へ反映する |
| 告知した受付上限を超える潜在需要 | 待ち客・取りこぼした機会として記録し、料理の失敗として扱わない |
| 開店前から告知した休業日 | 品質評価は据え置き。営業利益は得られない |
| 注文を受けた後の早仕舞い | 未提供として扱う。休業日に書き換えて減点を避けられない |

受付上限は朝に一度決め、客の種類を見てから恣意的に減らせないようにする。低い上限を選べば品質維持は容易になるが、売上・常連への提供機会・その店を知る客の増加が小さくなる。これを低リスク営業の正当な選択として残す。

品質の評判は最近の提供結果へ近づく有界値を使う。例として `翌日の評判＝0.8×現在値＋0.2×当夜品質` を比較対象にできるが、7日案の係数0.3から変更する必要があるかも未検証である。係数だけで成長速度を調整せず、回復速度と失敗の持続日数も測る。

受付対象の注文が0杯なら当夜品質を計算せず、評判は据え置く。受付対象があるのに全て断った日は0点となる。「売らなければ評価が上がる」経路を作らない。

21日版の時点では、画面に別の「知名度」ゲージを増やす必要はない。評判が安定した後は、満席日が増える、予測が安定する、常連の予約が入るといった効果で成長を表す。需要上限の引き上げだけに評判の価値を頼らない。

## 5. 常連と客層を、仕入れの理由にする

主な常連6人の基本嗜好は維持する。週が変わるたびに好物を入れ替えず、会話を覚えたことが次の仕入れに役立つようにする。

週2以降は、好物を何回出したかだけでなく、「来店予定が分かる」「取り置きを頼まれる」「同じ嗜好の知人を紹介する」のいずれかへ接続する。ただし全員に3種類とも付けず、人物ごとの違いに使う。重要な来店会話は売り切れで消滅させない。

モブ客は均等抽選だけから、夜勤・物流・宿泊などの客層の比率へ進める。例えば港の繁忙日はPOWER/FILLINGが多いと前日に分かる。同じ味を好む客しか来なくなる固定化は避け、通常客も残す。

客層ごとに独立した好感度・知名度・価格感応度を一度に新設しない。21日初版では「予定の客層」と「直近に満足して帰った割合」の記録から十分かを試す。長期版で客層選択が実際の経営方針になってから、継続来店の仕組みを追加する。

## 6. 予測は、不意打ちを増やすために曖昧にしない

| 時点 | 朝に見える情報 | プレイヤーの判断 |
|---|---|---|
| 週1 | 来店する常連、主な客層、狭い人数幅、混雑時間帯 | 必要な軸の具材と仕込みを揃える |
| 週2 | 前記に加え、数日先の混雑予告と取り置き依頼 | 生鮮をいつ買うか、設備購入後の需要があるかを考える |
| 週3 | 既知の予告が複数重なる日、最終週の来店予定 | 大量販売・品質・現金の残し方を決める |
| 長期版 | 曜日傾向、客層の変化、予測幅と直近実績 | 営業規模と在庫方針を継続的に見直す |

予告精度を上げる設備を売るために、元の予告を役に立たなくしない。予測幅が広い日でも、保存食や小さな仕込みで損失を限定できるようにする。初登場の高価な食材需要を、購入後に突然知らせない。

予測の評価は「当たった／外れた」だけでなく、表示した範囲に実績がどれだけ入ったかで行う。例えば80%予測区間を表示するなら、多数回の試行でおよそ80%が入ることを確認する。この80%は表示設計の例であり、現時点で採用する確率ではない。

## 7. 設備価格は増分利益と残営業日から決める

週2の最初の設備候補は、容量を増やす鍋と、腐敗を減らす保冷の2系統までに絞る。両方が必須になる設計を避け、設備なしでも品質重視・小規模営業で物語を終えられるようにする。

設備の効果は、同じ需要・同じ仕入れ判断条件で「設備あり／なし」を比較して測る。

```text
一日の増分利益 ΔΠ
  ＝追加売上
   −追加の使用食材原価
   −追加の仕込み・水・だし原価
   −追加の廃棄原価
   −追加の運営費

単純回収日数 ＝ 設備価格 / 一日平均の増分利益
残営業日で回収できる価格上限 ＝ 残営業日の増分利益の合計
```

廃棄が減る設備では「追加の廃棄原価」は負になる。食材購入費を全額費用にしたうえで、消費・廃棄をもう一度引かない。設備購入当日の現金支出と、上記の営業利益も分けて表示する。

増分利益が0以下なら、利益による回収はできない。週ごとに需要が変わる場合は平均値の割り算だけで判断せず、購入翌日以降の増分利益を日別に積み上げ、累計が購入額に届く日を回収日とする。購入当日から使える設備なら、その営業日も含める。

仮の計算例：鍋拡張で従来断っていた2杯を売れ、追加の食材・仕込み等を差し引いた1杯の貢献が22、設備による追加運営費が一晩8なら、増分利益は `2×22−8＝36／晩`。残り10営業日なら回収可能額の単純上限は360。試験上の目安を6〜8営業日回収と置くなら価格候補は216〜288になる。**これは価格決定ではなく、仮定した効果を価格へ変換する例**である。需要が1杯しか増えなければ同じ設備の採算は大きく変わる。

保冷の例：比較営業で削減できた廃棄原価が一晩18、追加運営費が3なら増分利益は15。残り6営業日の回収可能額は90にとどまる。もともと廃棄しないプレイヤーに、同じ保冷設備を利益目的で買わせる理由はない。

平均値だけで価格を決めず、低需要の経路でも購入後の運転資金が残るかを確認する。購入画面には翌朝の仕込み・運営費・予定仕入れと、次の定期支払いに必要な現金を表示する。

Day18以降の設備購入を当然の正解にしない。残り日数で回収できないなら見送れることが必要。期末に設備価値を成績へ加える場合は帳簿上の価値と現金を分ける。終値で全額買い戻す保証を入れると、終盤の設備購入にリスクがなくなるため、別の経済ルールとして検証する。

## 8. 物語に依存しない長期経営

21日版の完成後、長期経営は期間制の物語から別モードとして切り分ける。シナリオを長く引き延ばすのではなく、営業方針を変えながら店を維持することを目的にする。

| 論点 | 長期版の方針 |
|---|---|
| 評判の飽和 | 品質は最近の実績へ収束。評判100を毎週増やす仕組みにしない |
| 客数の飽和 | 商圏に上限を置き、予告付きの客層・曜日差で仕込みを変える |
| 成長 | 無限の杯数増加ではなく、廃棄・品切れ・運転資金の改善、異なる客層への対応 |
| 現金 | 安定経営の黒字を認める。黒字を消すための強制徴収を後から増やさない |
| 定期費用 | 営業規模に対応する継続費用を事前表示。物語の取り立てイベントの反復にはしない |
| 設備 | 維持費と効果を同じ期間で比較。買うだけで全問題が解消する上位互換を連鎖させない |
| 常連 | 物語の固定来店と分離し、営業履歴や曜日に応じて再来店する |
| 失敗 | 普通の仕入れミス1〜2回から回復できる資金幅を確認する。無条件の無料補填を前提にしない |
| 保存 | 日次の永続セーブを長期版までに用意。7日版のメモリ内やり直しだけに依存しない |

値付けは、固定価格で客層・仕込み・投資の差を検証した後の追加候補とする。最初に自由価格を足すと、客数や評判の改善ではなく最大利益の価格探しが中心になる可能性がある。

将来値付けを入れる場合も、最初は安価・標準・高付加価値の少数方針で試す。価格を上げると客が減る関係、高価な具材への期待、品質への不満をまとめて設計し、値段だけ変更できる状態にしない。これは長期版でも初回実装の必須機能ではない。

長期の費用は、売れた分に応じる費用、営業日ごとの費用、週など期間ごとの費用を分ける。休業すれば全部無料になる、販売数が増えるほど原価を二重請求する、といった抜け道や不整合を避ける。

## 9. 移行順序と検証の出口

| 段階 | 内容 | 次へ進める条件 |
|---|---|---|
| 1 | 7日版を仕上げる | 在庫ロット・購入単位・拒否・資金不足まで含め、複数方針で完走できる |
| 2 | 21日分の需要・常連・費用を紙上と独立モデルで作る | 曜日や物語を除いても、週2・週3に異なる判断がある |
| 3 | 設備を2系統まで追加 | 増分利益が測れ、選ばない方針にも成立する場面がある |
| 4 | 21日の通しプレイ | 週2以降に最適行動が固定されず、終盤の投資に残日数が効く |
| 5 | 物語を外した30日の営業 | 固定の主要客やイベント報酬がなくても収支が成立する |
| 6 | 90日・180日の長期検証 | 数値の発散・資金枯渇の固定化・無限購入の悪用・永久に最適な商品を検出できる |

比較する方針は、低価格食材の計画購入、保存品中心、常連への好物優先、容量へ早期投資、保冷優先、設備なしの小規模営業とする。同じ需要経路で比較し、最終現金だけでなく以下を出す。

- 実売杯数、受付上限超過の待ち客、引き受けた注文の未提供。
- 現金残高の最小値、翌営業に必要な運転資金、購入時期ごとの設備回収日。
- 食材の使用原価と腐敗原価、期末在庫の数量・期限・取得原価。
- 常連への提供機会、実際の品質、客層別の満足率。
- 一晩の操作件数と所要時間、週ごとの仕込み・設備・購入の選択率。

合格の方向性は、「投資しないと物語が終わらない」を避けつつ、「投資しても何も変わらない」を解消すること。通常日は安定して利益を出せるようになってよく、その上で予告された変化への備えや店の方針を選べる状態を目指す。

この文書の需要幅・供給量・回収日数・操作件数は、すべて将来試験の仮値である。7日版の実測結果を得るまでは、21日収支や長期の安定性が確認済みとは扱わない。
