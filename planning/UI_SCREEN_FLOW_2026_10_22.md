## 1. 決定事項
1. 一日の流れは **朝 → 市場 → 仕込み演出 → 開店 → 閉店 → 翌朝**。既存フェーズ（WAKE→PREP→OPEN→CLOSE→NEXT_DAY）に対応する。
2. **スマホ（レシピ／ニュース／SNS）は、どの画面からでもアイコンで開ける**。閉じれば元の画面へ戻る。
3. **市場は「会話画面」と「購入画面」だけで構成する**。鍋の素（小8杯80／中11杯110／大14杯140）は**食肉仲卸の購入画面**で買い、数字上はその時点で決まる。鍋の見た目は開店で見せ、市場には出さない。
4. **仕込みは操作なし**。MVPでは静止画かローディング風の演出。ここから先は戻れない。
5. **開店は1つの画面で、「会話」と「操作エリア」が同時に表示される**。操作エリアは「鍋」と「トッピング」が入れ替わる（＝「会話＆鍋」が、注文を受けると「会話＆トッピング」になる）。アイコンでスマホ画面へ。
6. **結果画面とゲームオーバーは、MVPでは静止画1枚を背景にし、成績・文・選択肢は文字で重ねる**。
7. 市場の店員との会話画面は「あってもよい」程度（イメージ未確定）。会話画面を流用し、MVPでは台本を書かない。
8. **（2026-10-24）操作エリアは画面の右側（案A）に置く**。立ち絵枠は400×490、会話枠は772×160で、文字は24px（1行30字×3行。標準のダミー台詞48字は2行）。
9. **（2026-10-24）左側（会話側）は鍋・トッピング共通**。左上に「Day N」と時間帯（宵／夜半／明）、所持金と評判は会話枠の右端にそろえる。スマホとログのアイコンは会話枠の右上に並べる。**「客 2/4」は出さない**。水・だしの縦の列（§9の案）はやめた。
10. **（2026-10-24）鍋の状態**：上から残り杯数（「9杯/14」）と濃さのゲージ、右寄せの「だし」「水」ボタン、一番下に鍋の絵。ボタンは名前→「残りN」→効果の順。**水を使えないときは説明なしでグレーアウト**。
11. **（2026-10-24）トッピング中は水・だしのボタンを出さない**。足したいときは鍋タブへ切り替える。代わりに、減点の予告に直し方（「鍋タブでだし +2」）を出し、鍋タブに「●」を付ける。椀の中身は切り替えても保持。
12. **（2026-10-24）具材の一覧は「タブ・4列」**：1タブ12個（4列×3行）。タブは具材が先、調味料が後。最初に開くのは具材。12個を超えたら「具材1」「具材2」…と増やす。MVPの品目は調味料5・具材12なので、タブは「具材」「調味料」の2つ。
13. **（2026-10-24）品目名は短縮名**（開店の操作エリアだけ。一覧は寸法表§6）。**大きい椀の絵は操作エリアの中**（一覧の下）に置く。椀の3枠は「いま椀に入っている中身」で、押せない。
14. **（2026-10-24）傷んだ在庫は「ボタンを2つに分ける」**：品目のボタンの右端に「傷N」の部分を付け、そこを押すと傷んだ在庫を使う（1段階の減点。現行の「(傷)」ボタンと同じ意味）。ボタンの数と位置は変わらない。

15. **（2026-10-24）スマホは右の枠と入れ替わる**（重ねない）。開店中も同じで、アイコンで開くと鍋・トッピングの操作エリアがスマホになり、「閉じる」で戻る（椀の中身は保持）。朝は「昨夜の成績 → スマホを見る → 市場」の順。
16. **（2026-10-24）スマホのタブは SNS／ニュース／レシピ**。**SNSはDMだけ**（常連になった客がメインもモブもDMを送ってくる。市場の顔なじみなども）。**ニュースはニュースだけ**。
17. **（2026-10-24）客足予報（総杯数・必要な味と具の数・在庫との過不足）はプレイヤーに出さない**。来店予定も明示しない。代わりの手がかり：
    - DMとニュースの文で客の多い少ないを匂わせる（例「ストの集会で今夜は港に人が多い」「今夜の港は人通りが少なそうだ」）。
    - 評判の横に「客足」を出す（提案：評判0〜19＝少ない／20〜44＝ふつう／45〜59＝多め／60〜70＝多い／71〜＝とても多い。需要表の区切りと同じ）。
    - 昨夜の成績と閉店の結果に「足りなかった杯数」（素材・鍋・断った の内訳つき）を出す。
    - 市場の画面に「今夜の見込み◯杯」は出さない。
    - **注意**：DESIGN.md 10.4「朝の一画面（SNSの客足予報）」と食い違う。設計書の更新と、予報なしの前提での自動試遊のやり直し（標準目標1500への到達率など）が要る。どちらもしまさん了承済み（2026-10-24）。
18. **（2026-10-24）市場では、会話の相手がいるときだけ立ち絵と名前を出す**。いないときは朝と同じく背景だけ。店選びは右の枠に6店の一覧と予算（残金・確保・使える）、「市場を出る」。
19. **（2026-10-24）ほかの画面の配置をMVPとして確定**：全画面で「左＝会話（開店と同じ位置）、右＝420×672の枠」を使い回し、右の枠の中身だけを入れ替える。朝は昨夜の成績、市場は店の一覧と予算、購入は商品の行（「3個 / 単価8 / 在庫4(新鮮3・傷1)」の2行の形）、閉店は今夜の結果の下に修繕基金と「次の日へ」。仕込み・結果・ゲームオーバーは全面の静止画に文字を重ねる。寸法は `claude/SCREENS_UI_LAYOUT_2026_10_24.md`。

## 2. 遷移図
```
朝 → 市場 → 仕込み演出 → 開店 → 閉店 → （翌朝へ。日付+1、前日成績を最初に表示）

朝    : 会話画面（自室の背景・立ち絵なし）＋右の枠に昨夜の成績 → スマホ（右の枠と入れ替わる）

開店  : 会話＋操作エリア。操作エリアは 鍋 → （注文を受ける）トッピング → （提供）鍋 …と入れ替わる
```

## 4. 開店の客1人分の流れ
```
来店：会話＋鍋（前回への2行・注文のやり取り）
  → 注文を受ける → 会話＋トッピング（注文カード・聞き直す・椀を組む）
  → 提供 → 会話＋鍋（反応・食事中の話・締め）→ 退店
複数杯の客（Day1の配達員3杯など）は 鍋 ⇄ トッピング を杯数ぶん繰り返す
```
- 会話の文字枠は常に見えるので、客の言葉を読み返しながら椀を組める（「会話から好みを読む」が核のため）。
- 状態が変わっても会話部分の位置は動かさない。入れ替わるのは操作エリアだけ。
- 1晩は常連3人＋モブ1組。

## 5. 既存ルールとの対応（変えないこと）
- フェーズは一方向。仕込み演出以降は戻れない。
- 市場に入って最初に開くのは食肉仲卸の購入画面。**鍋の素を買うまで他の店と「市場を出る」は押せない**（現行の順序を維持。仮置き）。所持金が80未満の日は、選択なしで端材屋から自動（クズ野菜ベース、8杯・濃さ1）。
- Day1：初日セット（210）は自動購入。市場の6店は閉まっている（Day2から解禁）。鍋の素の選択はDay1にもある。
- Day2：新人警官の立ち話が市場の前に入る。
- 水道代は市場を出るときに自動で払われる。日々の運営費は朝（WAKEに入った瞬間）に払われる。
- 鍋は水が残量12以下のときだけ足せる（2回まで）。
- 傷んだ在庫の判定は「押したボタンの種類」で決まる（現行仕様）。傷んでいない側を押せば、傷んだ在庫で補っても減点しない。
- 読む時間では鍋の煮詰まり・腐敗・客の待ちを進めない（ターン制。DESIGN 10.5.3）。時計のような表示は、急かす印象にならないようにする。

## 6. 操作エリアに必ず残す情報
トッピング：
- 注文カード（いつもの／今日の頼み）と「聞き直す」。聞き直しても料金・評判・評価は下がらない。
- 鍋の残量と濃さの小さな表示。
- 現在の椀（3枠）、大きい椀の絵、選べる具材の一覧（分類タブ）、減点の予告、提供／廃棄／断る の操作。
- レシピ保存・「いつもの」の操作（手順4-7）。
鍋：
- 残量・濃さ、だし・水の追加（それぞれ残り回数・在庫つき）。
共通（開店画面の枠）：
- スマホのアイコン、会話ログ（手順4-7）の入口。

## 9. 経緯：鍋の状態のレイアウト案（しまさん、2026-10-24 午前）と助言
※この節の「水・だしの縦の列」「時間帯と客数の部品」は、§1の9〜11でやめた。経緯として残す。

案の内容（スクリーンショットからの読み取り）：操作エリアの上に残り杯数と濃さのゲージ、その下に大きな鍋の絵。操作エリアの左に、水・だしのボタンと時計のような部品を縦に並べた細い列。上部に所持金、評判、鍋／トッピングのタブ。

5. 上部の評判は押せる見た目にしない。所持金の記号は¥。→ 採用。提供のたびに「+¥45」と出す案は未決。
6. MVP後でよいもの：残量と濃さで鍋の絵が変わる（水位・色・湯気）、水を足す演出。
