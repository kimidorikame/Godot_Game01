## 1. 終わりの条件

1. 本番UIのシーンで、**Day1の朝から最終日の結果画面まで、マウスだけで遊べる**（DebugPanelを使わずに）。
2. 各画面の部品の位置と大きさが寸法表どおり（数pxの丸めは可。10px以上ずれる箇所はplanか報告で挙げる）。
3. ゲームの挙動・数値・乱数の消費順・保存の形式は変えない。**全テストが通り、自動試遊30シード×13方針が新基準（`regulars_v2`）と全キー一致**。
4. しまさんが目で確かめられるよう、各画面のスクリーンショットを出す（§6）。

## 2. シーンの構成（推奨。planで確定）

- **ルート**：`scenes/game_root.tscn`（1280×720の `Control`）。`PlaySession` を子に1つ持つ。`changed` で全体を描き直し、`phase_entering` で表示だけの状態（スマホの開閉・タブ・鍋⇄トッピングの表示）を捨てる。描き直しの最後に `record_visible_event()`。
- **部品ごとに別の `.tscn`**（Godotエディタで配置を直せるように。座標はシーンに持たせ、スクリプトに直書きしない）：
  - 左側（共通）：上部の数字（日・時間帯／所持金・評判）、立ち絵枠、名前の札、会話枠、選択肢、スマホとログのアイコン
  - 右の枠：朝（昨夜の成績）、市場（店選び）、購入（食肉仲卸／ほかの店）、開店の操作エリア（鍋／トッピングのタブ）、閉店（今夜の結果・修繕基金）、スマホ
  - 全面：仕込み、結果、ゲームオーバー
- **見た目の共通設定**：`Theme` リソースを1つ作り、色（夜の画面の配色）と文字の大きさ（寸法表の値）をまとめる。部品は個別に色を持たない。
- **フォント**：日本語が確実に出るフォントを同梱する（推奨：Noto Sans JP。ライセンスはOFL。Q2）。
- **メインシーン**：`project.godot` のメインシーンを `game_root.tscn` にする。DebugPanelは別シーンとして残し、開発時に開けるようにする（Q1）。

## 3. 画面ごとの結線

読む問い・呼ぶ操作の対応は `PLAY_SESSION_API` §6 の表を使う。ここでは、APIの表に無い「UIの決まり」だけを書く。

### 3.1 共通（左側）
- 会話枠：`current_line()` の本文。**1枠＝24px・1行30字×3行**。入りきらない文は枠内でページ送り（右下の「▼」、続きがあるときは「▼続く」）。話し手が客なら名前の札と立ち絵枠を出し、地の文なら両方を消す。
- 会話を進める：会話枠のクリック（とキー操作。Q4）。`can_next_event()` なら `next_event()`、ページ送りが残っていれば先にページを送る。入力待ちの種類ごとの割り当ては §4 の表（plan で作る）。
- 選択肢：`current_choices()` があれば、立ち絵枠の上に縦に並べる（1つ400×52、間隔12）。
- 上部：日（`day_info()`）。開店中だけ時間帯ゲージ（宵／夜半／明）、それ以外は画面名（朝／市場／閉店）。所持金と評判は会話枠の右端にそろえる。評判の横の「客足」はCで足す（Bでは評判のみ）。
- 既読スキップ：DebugPanelと同じ条件（`can_skip_step()`）。置き場所はQ4。

### 3.2 開店の操作エリア
- タブ「鍋」「トッピング」は**表示の切り替えだけ**。`open_pot()`／`close_pot()` は呼ばない（会話を止めない）。注文を受けて椀を作る段階（`is_choosing_ingredients()`）になったら自動でトッピング、提供後（反応の段階）に自動で鍋へ戻す。タブで手でも切り替えられ、椀の中身はそのまま。
- 鍋：`pot_view()`。だし・水のボタンは右寄せ（だし左・水右）、名前→「残りN」→効果の順。押せないときは説明なしでグレーアウト。**押せる条件は `can_touch_pot()` と `can_add_water`／`can_add_dashi`**（Cで「椀を作っている途中も触れる」に変えるまでは、現行どおりトッピング中は多くの場面で押せない）。
- 鍋が尽きて保留の客（`is_shortage_pending()`）：自動で鍋タブを出し、「営業を続ける」（`resume_after_shortage()`）と「閉店」（`close_shop()`）を出す。**「営業を続ける」は、残り杯数が今の注文の杯数以上、かつ濃さが0でないときだけ押せる**（UIの条件。`PlaySession` の挙動は変えない）。
- トッピング：注文カード（`order_card_view()`）、椀の3枠（中身。押せない）、大きい椀の絵（一覧の下・仮の絵）、減点の予告（`sale_hint()` のコードから文を組む）、分類タブ（具材が先・調味料が後、1タブ最大12個＝4列×3行、12を超えたら「具材1」「具材2」…）、具材ボタン、鍋の小表示、提供・いつもの・保存・廃棄・断る。
  - 減点の予告の「鍋タブでだし +2」は、**だしで直せるとき（濃さが最小、かつ `can_touch_pot()` と `can_add_dashi` が真）だけ**出す（Bの間は、現行ルールでは出ない場面が多い）。
  - **傷んだ在庫は「ボタンを2つに分ける」**：`ingredient_options()` の新鮮側と傷んだ側を1つのボタンにまとめ、傷んだ在庫があれば右端に「傷N」の部分（28×40）を付ける。本体＝`select_ingredient(id, false)`、傷の部分＝`select_ingredient(id, true)`。
  - 短縮名：§5の表を使う（表示だけ）。
  - モブの団体：`mob_group_choice()` が空でなければ、提供の位置に「N人分を提供」「注文を断る」「残りN人に別の具材で挑戦する」を出す。
  - 聞き直す：注文カードの右（`can_reask()`）。再表示の文は会話枠に出す。
  - いつもの・保存：`recipe_adjust_buttons()`／`recipe_save_view()`。保存の段階（枠→名前）の見せ方はplanで提案。

### 3.3 右の枠（ほかの画面）
- 朝：昨夜の成績（`previous_day_record()`）。足りなかった杯数の内訳はCで足す（Bでは未提供の合計だけ）。「スマホを見る」で右の枠がスマホに替わる。Day1の朝は前日が無いので、右の枠を出さずにスマホから始める（plan で確認）。
- 市場：予算（`budget()`）、6店の一覧（`market_stalls()`。閉まっている店は薄く）、買った額、`today_base()`（「鍋の素 中11杯 買った」）、「市場を出る」。会話の相手がいるときだけ立ち絵。
- 購入（食肉仲卸）：鍋の素3段階（`prep_tiers()`、1つ124×119）、追加購入の商品の行（Day2から）、「店選びへ」（鍋の素を買うまで押せない）。
- 購入（ほかの店）：商品の行（2行。1行目：品名・タグ・「腐る」・価格・「買う」、2行目：「3個 / 単価8 / 在庫4(新鮮3・傷1)」）、この店で買ったもの、「店選びへ戻る」。
- 閉店：今夜の結果（`tonight_result()`）、修繕基金（`fund_view()`。対象の行を押して積む先を選ぶ、+10／+30）、「次の日へ」。基金は語りを読み終えてから押せる（現行どおり）。
- スマホ：右の枠と入れ替わる。タブはSNS／ニュース／レシピ。**SNSはCでDMに替えるまで「まだ新着はありません」の仮表示**（客足予報は出さない）。ニュース＝`phone_news()`、レシピ＝`phone_recipes()`。開店中に開くと、操作エリアがスマホに替わり、「閉じる（鍋・トッピングに戻る）」で戻る。
- 全面（仕込み・結果・ゲームオーバー）：左側の会話も消して、静止画1枚（仮の色）に文字を重ねる。結果は3ページ（成績・目標・物語）と出口（`exits()`）。

## 4. 操作の割り当て表（planで作る）

フェーズと入力待ちの種類ごとに、「どのボタン・クリックが、どの操作を呼ぶか」の表をplanに書くこと。少なくとも次を含める：WAKEの語りと「スマホを見る。」の入力待ち、WAKE→PREPへの進み方、PREP（仕込み3段階→市場→仕込み演出→OPEN）、OPEN（会話・注文・ADJUST・提供・反応・退店・時間帯の切り替わり・自動閉店）、CLOSE（語り→基金→次の日へ）、NEXT_DAY、RESULT、GAME_OVER。

`flow.advance_phase()` を呼ぶ場面（「市場へ」「開店する」「次の日へ」など）は、ボタンの文言とともに表にする。DebugPanelの[次のPhase]のような汎用ボタンは本番UIに置かない。

## 7. 決めてほしいこと（推奨付き）

- **Q1 メインシーンとDebugPanel**：推奨は「メインシーンを `game_root.tscn` にし、DebugPanelはエディタから単独で開ける（F6）ようにする」。代案：起動の引数か設定で切り替える。
- **Q2 フォント**：推奨はNoto Sans JP（OFL）を `assets/fonts/` に同梱し、`Theme` の既定にする。ライセンスの文書も同梱。代案：システムフォントに任せる（環境で見た目が変わるので非推奨）。
- **Q3 シーンとスクリプトの分け方**：部品ごとの `.tscn` と、描き直し（`refresh(session)`）の決まった形。親が子へ `session` を渡すか、子が親から取るか。
- **Q4 キー操作と既読スキップ**：会話を進めるキー（推奨：Enter・Space・左クリック）、既読スキップのボタンの置き場所（推奨：会話枠の右下、「▼」の左）、ログのアイコンで開くもの（推奨：右の枠に会話ログの一覧＝`talk_log_entries()`。スマホのタブには入れない）。
- **Q5 鍋⇄トッピングの自動切り替えのきっかけ**：どの問いの変化で切り替えるか（推奨：`is_choosing_ingredients()` が真になったらトッピング、反応の段階か次の客で鍋）。
- **Q6 スクリーンショットの撮り方**：推奨は、ウィンドウありで起動する撮影用のスクリプトで各状態を作り、`get_viewport().get_texture().get_image()` で保存。
- **Q7 文字の入りきらない箇所**：Godotのフォントで寸法表の文字が入らない場合（具材ボタンの2行、商品の行など）の扱い。推奨：入らない箇所を一覧で報告し、勝手に寸法を変えない（しまさんが決める）。
- **Q8 コミット分け**：推奨は、①ルート・Theme・フォント・左側（共通）、②右の枠：朝・市場・購入、③開店：鍋・トッピング・団体・保留（＋§5の1と3）、④閉店・全面（仕込み・結果・ゲームオーバー）（＋§5の2）、⑤スマホ・ログ・メインシーンの切り替え・UIの通しテスト・スクリーンショット。各コミットで全テストと3シード×13方針、最後に30シード×13方針。
